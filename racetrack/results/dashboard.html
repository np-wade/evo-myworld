How to read this

Every test shares one shape

Prompt → Report
One natural request in; a table of matches + saved files + a delivery manifest out. The whole assembly line is raced stage by stage.
The oracle trick
A privileged truth channel (an API, RSS, creator captions, or a self-authored answer key) grades the run — but the app is forbidden to use it. It must reach the data the normal web way.
Two-track scoring
The machinery is hard-scored against gold — that's what the optimizer chases. Judgment calls (picks, summaries) are advisory only, never in the leaderboard.
WON — raced & won its category LOST — ran but beaten DEFERRED — eligible, not yet raced

"catch the real edit, shrug off the churn"
Prompt: Watch these 12 pages; each run, report what changed since last run — what's new, what's gone, what moved.

Can a stateful monitor tell a real change from cosmetic churn — timestamps, rotating ads, reordered lists?

Snapshot & normalize → diff (raced) → classify real-vs-churn → report. Run 1 sets the baseline; run 2 diffs it.
Oracle (self-authored)
We inject known changes + churn traps into v2; the injection manifest is the answer key. 100% offline.

Diff race · 10 real changes + 23 churn traps

Score = F1 × (1 − false-alarm-rate). Every differ catches the real changes; the separator is which ones also fire on churn, and whether they point at the exact element.

candidatescoreF1false-alarmlocalizationstatus

The toy-vs-tool gap, on purpose: content-hash — the naive "did the page change?" approach — fires on 8 of 23 churn traps and catches zero real changes usefully. dom-diff suppresses all 23 while pointing at the exact element. Three combos already hit the ceiling of this fixture set, so the next move is a harder set that breaks them apart.
